# مناقش — FastAPI + React

المشروع مكوّن من `backend/` و`frontend/`. تصميم Lovable محفوظ، لكن العمليات والبيانات متصلة بـFastAPI وقاعدة البيانات. لا يوجد Login وهمي أو درجات وملفات تجريبية داخل المتصفح.

## المتطلبات

- Python 3.12 باستخدام Conda.
- Node.js 24 مع npm؛ هذه النسخة التي تم اختبار المشروع بها.
- PostgreSQL على Neon للتشغيل الفعلي، أو SQLite لتجربة محلية.

## 1. تشغيل الباك إند — Anaconda Prompt

لو بيئة `monaqesh` موجودة بالفعل، استخدم `conda activate monaqesh`. لو ليست موجودة:

```bat
conda create -n monaqesh python=3.12 -y
conda activate monaqesh
```

ادخل مجلد `backend` داخل المشروع المفكوك، ثم:

```bat
python -m pip install -r requirements.txt
python setup_env.py
```

الصق Connection String من Neon عندما يُطلب. الإدخال مخفي لأنه يتضمن كلمة مرور قاعدة البيانات. السكربت ينشئ `.env` ويولّد مفتاح أمان.

لو `.env` موجود بالفعل، عدّل قيمة `DATABASE_URL` فيه بدل إعادة السكربت. احتفظ بمعاملات `sslmode` و`channel_binding` الموجودة في رابط Neon. يقبل المشروع رابط `postgresql://` العادي ويجهزه لاستخدام Psycopg.

**للتجربة بدون Neon:** بدلاً من `python setup_env.py` استخدم `python setup_env.py --local`.

بعد تجهيز الإعدادات:

```bat
python -m alembic upgrade head
python -m app.cli seed-demo
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

- Alembic ينشئ الجداول، و`seed-demo` يضيف الحسابات فقط، بدون مادة أو تيمات أو درجات جاهزة.
- لا يتم حذف حساباتك أو تغيير كلمات مرورها عند إعادة الـSeed. تعارض هوية حساب موجود يوقف الاستيراد ويعرض خطأ.
- اترك هذا التيرمنال مفتوحًا.
- صفحة API: http://127.0.0.1:8000/docs
- اختبار الاتصال: http://127.0.0.1:8000/health/database

## 2. تشغيل الفرونت — تيرمنال جديد

ادخل مجلد `frontend`، ثم:

```bat
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

افتح http://127.0.0.1:5173 . الباك إند يظل يعمل في التيرمنال الأول.

الفرونت يستخدم افتراضيًا `http://127.0.0.1:8000`. لو العنوان مختلف، انسخ `frontend/.env.example` إلى `frontend/.env` وعدّل `VITE_API_URL`، ثم أعد تشغيل الفرونت. لا تضف `/api` في نهاية القيمة. ضع عنوان الفرونت في `CORS_ORIGINS` داخل `backend/.env` أيضًا لو غيّرت المنفذ أو الدومين.

**Connection String موجود في الباك إند فقط. الفرونت يحتاج عنوان الـAPI.**

## جرّب السيناريو كاملًا

1. ادخل بالدكتور، واضغط Create Course؛ المادة تبدأ كـDraft.
2. افتح المادة واضغط **Publish Course**؛ التسجيل وتكوين الفرق مفتوحان افتراضيًا. يمكنك فتحهما وإغلاقهما من Course Settings. حدد حجم التيم قبل إنشاء الفرق.
3. من Add TA ابحث عن `noha` وأضف المعيدة. من نفس الصفحة عدّل صلاحيات إدارة الدرجات وعرض التقارير والملفات.
4. اخرج وسجّل بأحمد. من Course Registration اعمل Register للمادة. كرر بكريم ليبقى عندك عضو ثانٍ.
5. ادخل بالدكتور، افتح المادة ثم Students، واضغط **Allow Create Team** بجوار أحمد.
6. ادخل بأحمد، افتح Project واعمل Create Team. كود الفريق يظهر للقائد فقط. ادخل بكريم واستخدم Join Team والكود كاملًا؛ ليس شرطًا أن يكون خمسة أرقام.
7. القائد يكتب عنوان ووصف المشروع ويختار Source ZIP وDocumentation PDF وREADME TXT/MD. Presentation PDF/PPTX اختيارية. اضغط **Save Draft & Files** لرفع الملفات فعليًا؛ الحد 25 MB لكل ملف.
8. بعد اكتمال الأعضاء والملفات اضغط **Confirm Final Submission**. هذا يقفل الملفات وعضوية الفريق ولا يوجد إعادة فتح في هذه المرحلة.
9. الدكتور أو المعيدة بالصلاحيات المطلوبة يفتح Project ثم View Team. من **Record a Manual Discussion Report** يسجل تقريرًا لكل طالب: الملخص والأسئلة والإجابات والنتائج.
10. من Assessments → Project → Manage Grades أدخل درجة كل طالب واضغط Save Changes.
11. الدكتور يضغط **Publish Recorded Grades**. كل درجة مشروع تحتاج تقريرًا مكتملًا لصاحبها. الطالب يرى درجته وتقريره هو فقط.
12. درجات Quiz/Midterm/Practical تُدخل وتُنشر من نفس قسم Assessments. يمكن تحديد Maximum Grade قبل إدخال أول درجة.

تعديل درجة أو إضافة نسخة مصححة من التقرير يعيد درجة الطالب لانتظار نشر الدكتور. Drop مرفوض بعد تسجيل درجات أو أثناء العضوية في تيم. قائد الفريق ينقل القيادة قبل مغادرة الفريق.

## ما تم ربطه

الدخول، تجديد التوكن، استعادة الجلسة بعد Refresh، Logout وLogout All وتغيير الباسورد، المواد ونشرها، تعيين المعيدين وصلاحياتهم، تسجيل/Drop، تحديد القادة، Create/Join/Leave/Transfer/Delete للتيمات، المساهمات، الرفع والتنزيل الحقيقي، قفل التسليم النهائي، تقارير المناقشة اليدوية، إدخال ونشر الدرجات، وسجل عمليات المادة.

الـDashboard يعرض بيانات محفوظة فعلًا. لا توجد درجات 87 ثابتة أو مواعيد أو إشعارات وهمية. الخط مُثبّت ضمن اعتماديات الفرونت ولا يعتمد على تحميل Google Fonts.

هذه نسخة المرحلة الأولى من الباك إند. AI/RAG/Gemini والمناقشة الصوتية المباشرة والمواعيد والمراقبة والإشعارات وطلبات المراجعة ومساحة العمل الفردية لم تُنفّذ بعد. زر Forgot Password يعرض التواصل مع الدعم؛ ليس خدمة استعادة تلقائية.

## الاختبارات

داخل `backend`:

```bat
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check app tests
```

داخل `frontend`:

```bat
npm test
npx tsc --noEmit
npm run build
```

اختبار المتصفح الكامل اختياري، ويستخدم قاعدة SQLite مؤقتة وحسابات مستقلة ولا يصل إلى Neon. أغلق السيرفرات على 8000 و5173 أولًا. من `frontend` ثبّت المتصفح:

```bat
npx playwright install chromium
```

ثم من جذر المشروع، داخل بيئة Conda التي فيها مكتبات الباك إند:

```bat
node scripts/check-integration.mjs
```

إذا Python عندك باسم مختلف حدد متغير `PYTHON_BIN`. سجل التحقق وما تم اختباره موجود في `VALIDATION.md`.

## أماكن الكود

| المسار | المحتوى |
|---|---|
| backend/app/routers | API والعمليات حسب الموضوع |
| backend/app/core | الإعدادات والأمان والصلاحيات |
| backend/app/models.py | تعريفات الجداول |
| backend/alembic | إنشاء الجداول وإدارة تعديلات شكلها |
| frontend/src/services/api.ts | الاتصال، Bearer Token، التجديد والأخطاء |
| frontend/src/services/workspace.ts | تحميل البيانات المسموح بها وتحويلها للشاشات |
| frontend/src/services/contracts.ts | أشكال ردود الباك إند |
| frontend/src/features/monaqesh | الشاشات بنفس التصميم الأساسي |

ملفات الرفع تتحفظ في `backend/storage` افتراضيًا، والداتابيز تحفظ بيانات الملفات وبصماتها. لم يتم تضمين أسرار الاتصال أو قاعدة بيانات اختبار أو ملفات مستخدمين في الـZIP.
